Auctum Ledger — Education Module

Masterclass SaaS UI Specification

The Readiness Surface: A Design System for Competence-as-Authority

---

0. Foundational Thesis

The Education tab is not a course catalog. It is the credential authority surface for a platform where competence gates action. The UI must embody this inversion: learning is summoned at the point of work, not browsed in a library.

This specification defines a design system where:

· Credentials are first-class objects with states, not completion badges
· Blocked actions explain themselves and state their remedy inline
· Calibration is continuous, visualized as drift over time, not a pass/fail moment
· Content versions create staleness, surfaced with the same visual weight as Trust score modelVersion changes
· Vietnamese-first is a design constraint, not a translation afterthought

---

1. Design Philosophy: Five Principles

1.1 Authority as Interface

Every credential display answers three questions in one glance:

1. What can I do? (authority scope)
2. Until when? (expiry state)
3. Against what? (content version)

```
┌─────────────────────────────────────────────────────────────────┐
│  CUPPER_TIER_2                                          ● ACTIVE │
│  ───────────────────────────────────────────────────────────────│
│  Authority: Independent standard checks · Tier 1 exceptions     │
│  Issued: 2024-03-15 · Expires: 2025-03-15 · 172 days remaining  │
│  Content: cupping-sop v4.2 · Reference: SOP §1.2, §5.1–5.2      │
└─────────────────────────────────────────────────────────────────┘
```

Anti-pattern: A progress bar showing "80% complete" for a credential. Completion is not the metric—authority is.

1.2 Evidence Before Economy

Every economic claim renders after its evidence. In practice:

```html
<!-- Correct: proof precedes price -->
<article class="lot-record">
  <header class="lot-verification">
    <VerificationBadge tier="audit-verified" />
    <SourceTimestamp value="2024-11-28T09:14:00+07:00" />
    <LedgerRef id="lot-2847-v3" />
  </header>
  <div class="lot-economics">
    <FarmgatePrice amount="3.20" currency="USD" basis="ledger-entry-48291" />
    <PriceWaterfall />
  </div>
</article>
```

CSS enforcement: .lot-economics cannot render without a preceding .lot-verification sibling. This is a design-system constraint, not a style preference.

1.3 Blocks Explain Themselves

The cardinal rule from Trust, applied to competence:

Every block states its cause and its remedy in the same breath.

1.5 Staleness Is Visible

When content versions supersede, credentials enter a distinct visual state:

State Visual Treatment Semantic
Active Solid border, full saturation Full authority
Expiring Amber left-edge accent Renewal window open
Stale Dashed border, muted saturation Valid but superseded
Lapsed Gray, strikethrough on authority text Suspended

```css
.credential[data-state="stale"] {
  border-style: dashed;
  border-color: var(--color-ink-muted);
  opacity: 0.85;
}

.credential[data-state="stale"]::after {
  content: "Content v4.2 superseded by v4.3";
  font: var(--font-mono-xs);
  color: var(--color-warning);
}
```

Grading logic:

```typescript
interface AdjudicationKey {
  correctTier: 'TIER_1' | 'TIER_2' | 'TIER_3';
  correctDisposition: 'RELEASE' | 'DOWNGRADE' | 'REJECT_CLAIM' | 'RE_VERIFY';
  adjustedPriceTolerance: 0.01; // USD
  correctFault: 'PRODUCER' | 'COLLECTOR' | 'PLATFORM';
}

function gradeAdjudication(
  response: AdjudicationResponse,
  key: AdjudicationKey
): AdjudicationResult {
  const tierCorrect = response.tier === key.correctTier;
  const dispositionCorrect = response.disposition === key.correctDisposition;
  const priceCorrect = Math.abs(response.adjustedPrice - key.adjustedPrice) 
    <= key.adjustedPriceTolerance;
  const faultCorrect = response.fault === key.correctFault;
  
  return {
    passed: tierCorrect && dispositionCorrect && priceCorrect,
    breakdown: { tierCorrect, dispositionCorrect, priceCorrect, faultCorrect },
    // Fault attribution is feedback, not pass/fail
  };
}
```

Privacy enforcement in code:

```typescript
// Drift data access control
const DRIFT_DATA_ACCESS = {
  self: ['read', 'export'],
  qc_manager: ['read', 'annotate'],
  admin: ['read'],
  // Explicitly excluded roles
  counterparty: [],
  public: [],
  trust_computation: [], // Never
};

function canAccessDriftData(
  viewer: User,
  subject: User,
  action: 'read' | 'annotate' | 'export'
): boolean {
  if (viewer.id === subject.id) {
    return DRIFT_DATA_ACCESS.self.includes(action);
  }
  if (viewer.roles.includes('QC_MANAGER') && 
      viewer.managedUsers.includes(subject.id)) {
    return DRIFT_DATA_ACCESS.qc_manager.includes(action);
  }
  if (viewer.roles.includes('ADMIN')) {
    return DRIFT_DATA_ACCESS.admin.includes(action);
  }
  return false;
}
```

8. Design System Governance

8.1 The Hard Rules

These are non-negotiable in the design system:

1. No credential display without state. Every credential shows: type, state, expiry, content version.
2. No block without remedy. Every blocked action states its cause and shortest path to unblock.
3. No drift data in Trust. The _accessControl field on calibration points is enforced server-side.
4. No hardcoded thresholds in content. Lesson content references policy modules; CI fails on hardcoded numbers.
5. No D-track payment gating. Enforced in code, not policy.
6. No ad-hoc navigation. Teaching is summoned inline; the Education tab is a readiness surface.
7. No integer variance. All calibration values are decimal(5,2).

8.3 The Component Contract

Every component that displays credential-gated content must:

1. Accept a credentialState prop
2. Render differently for each state
3. Provide an onBlocked callback when action is gated
4. Never silently fail

```tsx
// Example contract
interface GatedActionProps {
  credentialType: string;
  credentialState: 'active' | 'expiring' | 'stale' | 'lapsed' | 'missing';
  onAction: () => void;
  onBlocked: (remedy: RemedyPath) => void;
  children: React.ReactNode;
}

function GatedAction({ credentialState, onAction, onBlocked, children }: GatedActionProps) {
  if (credentialState === 'active') {
    return <div onClick={onAction}>{children}</div>;
  }
  
  return (
    <BlockedActionPanel
      credentialType={credentialType}
      state={credentialState}
      onBeginRemedy={() => onBlocked(remedyPath)}
    />
  );
}
```

9. Summary: The Design Doctrine

The Education module UI is built on a single inversion:

The platform does not have an education feature. The platform has authority rules, and education is how you earn them.

This means:

· The tab is a readiness surface, not a catalog
· Teaching is summoned at the point of work, not browsed
· Credentials have states (active, expiring, stale, lapsed, probationary), not completion badges
· Calibration is continuous drift measurement, not a one-time pass
· Blocks explain themselves and state their remedy in the same breath
· Vietnamese is first, not translated
· Offline is assumed, not accommodated
· Drift data is private, never Trust, never counterparty

The visual system inherits the Auctum Ledger's 170 tokens: parchment, Compass Navy, Fraunces/Archivo/IBM Plex Mono, gold reserved for proven claims. The motion system uses the spring ease for credential state transitions, revealing hierarchy and state change. The spacing system is 4px base. The typography scale is Major Third, with Vietnamese accommodation.

Every component answers three questions: What can I do? Until when? Against what?
